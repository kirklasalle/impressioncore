## Plan: ImpressionCore Model Offerings + Builder Presets

Deliver a two-pass outcome: first a safe refactor + forensic audit that stabilizes model-offering wiring (Builder -> model registration -> Dashboard harness), then a second-draft documentation package that formalizes 39M/50M/504M initial offerings and introduces C1 (Colossus) as a planned series placeholder.

**Steps**

1. Phase 1 - Baseline Validation (blocks all later steps)
1. Confirm live model artifact baseline and declared offering IDs for this cycle: `B1-39M`, `B2-50M`, `B3-504M`.
1. Verify Builder and Dashboard currently discover models from canonical path services before touching code.
1. Build a mismatch ledger (declared parameter count vs config/runtime signature) to include in audit.

1. Phase 2 - Minimal Safe Refactor (parallelizable in sub-steps)
1. Centralize Builder preset definitions into one canonical source so CLI and Builder UI consume identical offerings. *depends on Step 1*
1. Add three explicit preset objects (39M, 50M, 504M) with stable IDs, labels, target hardware hints, and expected checkpoint conventions. *parallel with next sub-step*
1. Wire Builder template/walkthrough selection UI to these preset IDs and persist selection in Builder model/training config stores. *parallel with previous sub-step*
1. Harden API-side validation to enforce allowed preset IDs and required fields (prevent drift from ad hoc JSON edits). *depends on prior two sub-steps*
1. Ensure dashboard model-list/harness registration can surface these offerings using consistent metadata keys. *depends on preset schema finalization*

1. Phase 3 - Pre-Draft Audit (required before second draft)
1. Conduct focused code audit for regression risk in touched flow: preset lookup, config save/load, model discovery, and training start.
1. Record concrete findings by severity (bugs/risk/behavior changes) and include unresolved residual risks.
1. Verify no frontend-destructive changes (additive-only guarantee).

1. Phase 4 - Documentation First Draft Artifacts
1. Create a model-offering forensic report documenting each offering with: architecture signature, training lineage, dataset/training sources, expected usage, and known integrity caveats.
1. Include explicit section for C1/Colossus as planned next series, with current evidence references and scope boundary (planned, not production offering in this cycle).
1. Add operational backup section: required artifact set, checksum procedure, and restore verification checklist.

1. Phase 5 - Second Draft Production
1. Produce second-draft narrative report with tightened executive summary, offering matrix, builder preset UX behavior, dashboard availability flow, and rollout gates.
1. Include implementation changelog appendix mapping code edits to user-visible behavior.
1. Include acceptance criteria and QA sign-off checklist.

1. Phase 6 - Verification and Handoff
1. Run/validate relevant backend routes and Builder flows for preset select -> configure -> start.
1. Validate dashboard/harness listing includes the three offerings with expected labels.
1. Verify docs are IDS-ready: standardized header/tags and cross-links.
1. Deliver concise handoff with findings-first summary and next-step options.
