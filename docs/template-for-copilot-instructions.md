# GitHub Copilot Instructions

This document provides guidelines for effectively using GitHub Copilot within the ImpressionCore project.

## Getting Started with Copilot

1. Ensure you have GitHub Copilot installed in your IDE
2. Make sure you have an active GitHub Copilot subscription
3. Enable Copilot for the ImpressionCore workspace

## Best Practices

### Code Generation

- Write clear and descriptive comments before requesting Copilot suggestions
- Review all generated code thoroughly before accepting suggestions
- Ensure generated code follows our project's coding standards
- Validate that generated code includes proper error handling
- Test generated code thoroughly before committing

### Documentation

- Use Copilot to help document functions and classes
- Request suggestions for docstrings and comments
- Verify that generated documentation is accurate and follows our documentation standards

### Testing

- Leverage Copilot for generating test cases
- Use descriptive comments to get relevant test scenarios
- Ensure generated tests cover edge cases
- Validate test coverage for generated code

## Project-Specific Guidelines

### Model Development

- Use Copilot to assist with model architecture implementations
- Request suggestions for optimization techniques
- Generate boilerplate code for model components

### API Development

- Generate API endpoint implementations
- Use Copilot for request/response validation code
- Implement error handling patterns

## Code Review Guidelines

When reviewing Copilot-generated code:

1. Check for security vulnerabilities
2. Verify performance implications
3. Ensure compliance with project architecture
4. Validate error handling implementation
5. Confirm proper logging and monitoring

## Limitations and Considerations

- Always verify generated code for correctness
- Don't rely on Copilot for critical business logic
- Review security-sensitive code manually
- Test generated code thoroughly
- Keep documentation up-to-date with changes

## Tips for Better Suggestions

1. Write clear, descriptive comments
2. Break down complex tasks into smaller components
3. Use consistent naming conventions
4. Provide context in comments when needed
5. Include type hints and annotations

## Security Guidelines

- Never commit sensitive information in comments
- Review generated code for security vulnerabilities
- Validate input/output handling
- Ensure proper authentication/authorization checks
- Review dependency suggestions carefully

## Troubleshooting

If Copilot suggestions aren't helpful:

1. Try rephrasing your comments
2. Break down the problem into smaller parts
3. Provide more context in comments
4. Check if similar code exists in the project
5. Consult the project documentation

## Maintenance

- Regularly update Copilot extension
- Review and update these guidelines as needed
- Share feedback and improvements with the team
- Document common patterns and solutions

## Version Control Integration

- Write clear commit messages for Copilot-generated code
- Reference relevant documentation or issues
- Follow project branching strategy
- Include tests for generated code

Remember that Copilot is a tool to enhance productivity, not replace careful development practices. Always review, test, and validate generated code before committing to the project.
