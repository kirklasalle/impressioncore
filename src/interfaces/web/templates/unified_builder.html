02 / MODEL DEFINITION

Architecture

Native research path

ImpressionCore B3

Runtime source is reported by the local backend.

Source not yet available

Objective: prefix-to-next-token. Each record supplies one prefix and one next-token target, not all-position causal language-model training. The native router attends across the entire prefix. This runner trains text only; multimodal training is not implemented here.

Offering identity is not a parameter count.

B-series offerings retain their official dimensions as references. Legacy B3 values estimate far larger than the 504M name implies; they are not silently mapped to a native model. A run reports the actual instantiated parameter count.

Native configuration

Explicitly adopt the backend’s B3Config template, then review every dimension. This does not load a model or replace the offering reference.

A JSON object containing exactly the documented src.core.models.impressioncore_b3_architecture.B3Config fields is required for training. The server validates dimensions and resource limits. Use null to remove the native configuration.

03 / INPUTS

Local text data

No automatic scanning

Dataset source

Paths refer to files on the machine running Flask, not your browser’s filesystem. UTF-8 text / JSONL only, at most 8 MiB and 4,096 records. Records need at least two tokens to participate in training. Only select files you intend this local application to read.

A distinct held-out path is required for evaluation. Never report training loss as a benchmark score.

Bounded inspection

Save this project and run preflight to inspect samples, file size, and configuration compatibility.

04 / VOCABULARY

Tokenizer artifact

Use a local tokenizer

An existing tokenizer.json is required, at most 32 MiB. Its vocabulary must exactly match native vocab_size. Fine-tuning also requires the checkpoint’s exact tokenizer hash. No download or automatic vocabulary resizing.

Vocabulary and artifact hash are available after preflight.

Tokenizer preparation is separate

Bring a real local tokenizer.json artifact. The legacy tokenizer page contains simulated training; it is not a verified preparation path and this workspace does not invoke it.

Training configuration

Text · prefix-next-token

Initialization

Fine-tuning starts a new optimizer from a same-project native checkpoint with matching configuration and tokenizer hash; it is not exact resume. For a first run, explicitly choose Train from scratch.

Optimization & limits

Native execution uses FP32 and micro-batch 1. Legacy precision, scheduler, warmup, and checkpoint-directory settings are reference metadata, not controls for this runner.
