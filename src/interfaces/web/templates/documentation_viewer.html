ImpressionCore: Full User Guide

ImpressionCore is a versatile Python library designed for efficient tokenization of both text and images. It serves as a foundational component for building multimodal AI models, particularly those based on transformer architectures.

🎯 Core Philosophy

Provide a robust and configurable system for handling the crucial first step in many AI pipelines: getting data into a format the model can understand.

Core Features

  • Dual Tokenization: Handles both text (using Byte-Pair Encoding - BPE) and images (using learned Patch-Based Vector Quantization - VQ)
  • Efficiency: Designed for good compression and performance, especially relevant for image tokenization
  • Configurability: Uses JSON files for configuring model architectures and training parameters
  • Training Framework: Includes scripts and utilities to train your own text and image tokenizers on custom datasets
  • Web Interface: Provides an interactive web UI (served via Flask) for exploring features, setting up the environment, and experimenting with tokenizers
  • Command-Line Tools: Offers utilities for tokenizing content, converting token formats, and analyzing token distributions
  • Modularity: Built with components like `ModalEngine` for potentially extending to other modalities in the future
  • Transformer Architecture: Implements a brain-inspired architecture with attention mechanisms, feed-forward networks, and more

Who is this guide for?

This guide is intended for:

  • Developers: Who want to integrate ImpressionCore into their AI projects
  • Researchers: Exploring multimodal tokenization techniques
  • Students: Learning about text and image processing for deep learning
  • Users: Who want to utilize the provided web interface and tools for tokenization tasks

A basic understanding of Python, deep learning concepts (especially transformers), and command-line usage is beneficial.

⚠️ System Requirements

  • Python 3.8 - 3.10 (recommended)
  • NVIDIA GPU with CUDA support (highly recommended)
  • 16GB RAM minimum (32GB+ recommended)
  • 20GB free disk space

Installation

Follow these steps to install ImpressionCore and its dependencies.

Prerequisites

  • Git: Required for cloning the repository. (Download Git)
  • Python: Ensure you have a compatible Python version (3.8-3.10 recommended) installed and added to your system's PATH. (Download Python)
  • C++ Build Tools (Windows): If installing certain dependencies on Windows (especially if building from source is needed), you might need Microsoft C++ Build Tools. You can get these via the Visual Studio Installer (select "Desktop development with C++").

Cloning the Repository

Open your terminal or command prompt and clone the ImpressionCore repository:

git clone <repository_url> # Replace <repository_url> with the actual Git URL
cd impressioncore

Setting up the Python Environment

It is strongly recommended to use a virtual environment to manage dependencies and avoid conflicts with other Python projects.

  1. Navigate to the project root directory: 
    cd path/to/impressioncore
  2. Create a virtual environment: (Replace `venv` with your preferred environment name if desired) 
    python -m venv venv
  3. Activate the virtual environment:
    • Windows (cmd.exe): 
      venv\Scripts\activate.bat
    • Windows (PowerShell): 
      .\venv\Scripts\Activate.ps1

      (You might need to run Set-ExecutionPolicy RemoteSigned -Scope CurrentUser first if you encounter script execution errors).

    • Linux/macOS (bash/zsh): 
      source venv/bin/activate

    Your terminal prompt should now indicate that the virtual environment is active (e.g., (venv) C:\Projects\impressioncore>).

Installing Dependencies

Once the virtual environment is active, install the required Python packages.

  1. Install Core Dependencies:

    The primary dependencies are listed in requirements.txt. PyTorch is usually installed separately for GPU support (see next section).

    pip install -r requirements.txt

    *(Note: If requirements.txt doesn't exist or is incomplete, you might need to install packages like Flask, Flask-Cors, Flask-Sock, numpy, Pillow, torch, torchvision, torchaudio, scikit-image, matplotlib, markdown etc., manually or via pip install -e . if a setup.py is present).*

  2. Install PyTorch (CPU-only fallback):

    If you are not setting up GPU support, you can install the CPU version of PyTorch:

    pip install torch torchvision torchaudio
  3. Install for Development (Editable Mode):

    If you plan to modify the ImpressionCore source code, install it in editable mode:

    pip install -e .

    This links the installation to your source code directory, so changes are reflected immediately.

GPU Setup (Highly Recommended)

Using an NVIDIA GPU significantly accelerates training and inference tasks, especially for image tokenization and model operations.

Why Use a GPU?

  • Speed: Massively parallel processing capabilities speed up computations.
  • Necessity: Many deep learning models are too computationally intensive to run effectively on a CPU.
  • Image Tokenization: The VQ process benefits greatly from GPU acceleration.

ImpressionCore may provide a script to simplify PyTorch installation with the correct CUDA version. Check for a script like tools/install_pytorch_cuda.py.

If available, run it from your activated virtual environment:

python tools/install_pytorch_cuda.py

This script typically attempts to:

  1. Detect your system's installed CUDA Toolkit version.
  2. Uninstall any conflicting PyTorch versions.
  3. Install the correct PyTorch build matching your CUDA version.

If the automatic script is unavailable or fails, follow these steps:

Ensure you have the latest official NVIDIA drivers for your specific GPU model.

  • Download from: NVIDIA Driver Downloads
  • Follow the installer instructions. A reboot may be required.
  • Verify installation by checking the NVIDIA Control Panel or using nvidia-smi in the terminal (if installed with the driver).

2. Install CUDA Toolkit

PyTorch requires the NVIDIA CUDA Toolkit to interact with the GPU.

  • Check Compatibility: Refer to the PyTorch website (https://pytorch.org/) for the recommended CUDA versions compatible with the desired PyTorch version. Common recent versions are 11.8 and 12.1.

GPU Troubleshooting

  • `torch.cuda.is_available()` returns `False`:
    • Incorrect PyTorch version installed (CPU-only or wrong CUDA build). Reinstall using the correct command from the PyTorch website.
    • CUDA Toolkit installation issue or not found in PATH. Verify nvcc --version.
    • NVIDIA driver issue. Reinstall/update drivers.
    • Incompatible hardware (GPU too old).
  • "No matching distribution found for torch":
    • Unsupported Python version (try 3.8-3.10).
    • Network issue preventing download from PyTorch index.
    • Typo in the installation command or index URL.
  • CUDA Out of Memory Errors:
    • Your GPU doesn't have enough VRAM for the task (model size, batch size). See Notes for GTX 1050 Ti.
    • Other processes might be using GPU memory. Check with nvidia-smi.
    • Memory leak in the code.

Notes for GTX 1050 Ti (4GB VRAM)

The GTX 1050 Ti is a capable card but has limited VRAM (4GB). Keep this in mind:

  • Model Size: Training large models from scratch will be very difficult or impossible. Focus on smaller models or fine-tuning.
  • Batch Size: Use small batch sizes (e.g., 1, 2, 4, 8) during training and inference to fit within memory limits.
  • Half Precision (FP16/BF16): Use model.half() or torch.cuda.amp (Automatic Mixed Precision) to reduce memory usage, potentially at the cost of some numerical stability.
  • Gradient Checkpointing: Enable during training (model.gradient_checkpointing_enable()) to trade computation time for memory savings.
  • Quantization: For inference, consider 8-bit quantization (torch.quantization.quantize_dynamic) to significantly reduce model size and memory footprint.
  • Environment Variables: The setup.html page might suggest setting PYTORCH_CUDA_ALLOC_CONF=max_split_size_mb:X (e.g., X=512 or lower) to optimize memory allocation for smaller GPUs.

Tokenization Deep Dive

This section explores the text and image tokenization capabilities of ImpressionCore in more detail.

Understanding Tokenization

Tokenization breaks down complex data (like a paragraph of text or a high-resolution image) into smaller, manageable units (tokens) that a machine learning model can process. Each unique token is typically assigned an integer ID.

  • Text: Tokens can be words, subwords (like token, ization), or even characters.
  • Images: Tokens often represent visual patterns within small patches of the image.

Text Tokenization (BPE)

ImpressionCore uses Byte-Pair Encoding (BPE) for text.

How BPE Works

  1. Initialization: Start with a vocabulary containing all individual characters present in the training corpus.
  2. Iteration: Repeatedly count all adjacent pairs of tokens (symbols) in the corpus.
  3. Merging: Find the most frequent pair (e.g., 't', 'h') and merge it into a new, single token ('th'). Add this new token to the vocabulary.
  4. Repeat: Continue merging the next most frequent pair until the desired vocabulary size is reached or no more merges are possible.
  5. Tokenization: To tokenize new text, apply the learned merges greedily in the order they were learned.

Using the BPETokenizer

The src.tokenization.bpe.BPETokenizer class handles text tokenization.

from src.tokenization.bpe import BPETokenizer

# --- Loading ---
# Load a pre-trained tokenizer (replace path)
try:
    tokenizer = BPETokenizer.load("data/tokenizers/text_tokenizer.json")
except FileNotFoundError:
    print("Tokenizer file not found. Train one first.")
    # Handle error or train a new one
    exit()

# --- Encoding ---
text = "Hello ImpressionCore world!"
# Get token IDs
token_ids = tokenizer.encode(text)
print(f"'{text}' -> IDs: {token_ids}")
# Get token strings
tokens = tokenizer.tokenize(text)
print(f"'{text}' -> Tokens: {tokens}")

# --- Decoding ---
reconstructed_text = tokenizer.decode(token_ids)
print(f"IDs {token_ids} -> '{reconstructed_text}'")

# --- Vocabulary ---
print(f"Vocabulary Size: {tokenizer.vocab_size}")
# print(f"Vocabulary: {tokenizer.get_vocab()}") # Can be large

Special Tokens

Special tokens are used to signal specific things to the model:

  • <unk> (ID 0): Represents words not found in the vocabulary.
  • <pad> (ID 1): Used to make sequences in a batch the same length.
  • <bos> (ID 2): Marks the beginning of a sequence.
  • <eos> (ID 3): Marks the end of a sequence.
  • <mask> (ID 4): Used in tasks like Masked Language Modeling.

You can control their inclusion during encoding/decoding:

# Encode with BOS/EOS
token_ids_special = tokenizer.encode(text, add_special_tokens=True)
print(f"With BOS/EOS: {token_ids_special}")

# Decode, skipping special tokens in the output string
reconstructed_skip = tokenizer.decode(token_ids_special, skip_special_tokens=True)
print(f"Decoded skipping special: '{reconstructed_skip}'")

Image Tokenization (VQ)

ImpressionCore uses a patch-based Vector Quantization (VQ) approach.

How Patch-Based VQ Works

  1. Patching: Divide the input image into a grid of non-overlapping patches (e.g., 16x16 pixels).
  2. Encoding: Pass each patch through an encoder network (often a CNN or transformer) to get a feature vector (embedding).
  3. Quantization: Find the closest vector in a pre-learned "codebook" (a set of representative feature vectors). The *index* of this closest codebook vector becomes the token ID for that patch.
  4. Decoding (Optional): To reconstruct the image, retrieve the codebook vectors corresponding to the token IDs and pass them through a decoder network to generate image patches, which are then reassembled.

Using the ImageTokenizer

The src.tokenization.image.ImageTokenizer class handles image tokenization. It often requires PyTorch and a GPU.

import torch
from PIL import Image
from src.tokenization.image import ImageTokenizer
from torchvision import transforms # Usually needed for preprocessing

# --- Loading ---
device = torch.device('cuda' if torch.cuda.is_available() else 'cpu')
try:
    tokenizer = ImageTokenizer.load("data/tokenizers/image_tokenizer.pt").to(device)
    tokenizer.eval() # Set to evaluation mode
except FileNotFoundError:
    print("Image tokenizer file not found. Train one first.")
    exit()

# --- Image Preparation ---
image_path = "examples/sample_image.jpg" # Replace with your image
try:
    image = Image.open(image_path).convert('RGB')
except FileNotFoundError:
    print(f"Image file not found: {image_path}")
    exit()

# Preprocessing often involves resizing and converting to tensor
# The exact transform depends on how the tokenizer was trained
preprocess = transforms.Compose([
    transforms.Resize((tokenizer.image_size, tokenizer.image_size)),
    transforms.ToTensor(), # Converts to [C, H, W] tensor in [0, 1] range
    # Add normalization if the tokenizer expects it
    # transforms.Normalize(mean=[0.485, 0.456, 0.406], std=[0.229, 0.224, 0.225])
])
image_tensor = preprocess(image).unsqueeze(0).to(device) # Add batch dimension

# --- Encoding ---
with torch.no_grad(): # Disable gradient calculation for inference
    tokens = tokenizer.encode(image_tensor) # Get token IDs (likely a flattened list or grid)
print(f"Image encoded to {tokens.shape} tokens.") # Shape depends on implementation

# --- Decoding ---
with torch.no_grad():
    reconstructed_tensor = tokenizer.decode(tokens) # Get reconstructed image tensor

# --- Postprocessing ---
# Convert tensor back to PIL Image for saving/viewing
reconstructed_image = transforms.ToPILImage()(reconstructed_tensor.squeeze(0).cpu())
reconstructed_image.save("reconstructed_sample.jpg")
print("Reconstructed image saved.")

# --- Quality Metrics (Optional) ---
# ssim = tokenizer.compute_ssim(image_tensor, reconstructed_tensor)
# psnr = tokenizer.compute_psnr(image_tensor, reconstructed_tensor)
# print(f"SSIM: {ssim:.4f}, PSNR: {psnr:.2f} dB")

Image Tokenizer Architecture

  • Encoder: Maps image patches to latent vectors.
  • Codebook: A learnable tensor (num_tokens, embedding_dim) storing the representative vectors.
  • Quantization: Finds the nearest codebook entry for each patch embedding (using Euclidean distance or dot product).
  • Decoder: Reconstructs image patches from codebook vectors.
  • Loss Function: Training typically involves reconstruction loss (e.g., MSE, L1) and a codebook loss (encouraging codebook vectors to be used and updated).

Analyzing Tokens

Understanding the distribution and characteristics of tokens can be useful.

from collections import Counter
import math
import matplotlib.pyplot as plt

# Assume 'token_ids' is a list of integers
token_counts = Counter(token_ids)
num_unique = len(token_counts)
total_tokens = len(token_ids)

print(f"Total Tokens: {total_tokens}")
print(f"Unique Tokens: {num_unique}")

# Entropy (measure of information/randomness)
entropy = -sum((count / total_tokens) * math.log2(count / total_tokens)
               for count in token_counts.values())
print(f"Token Entropy: {entropy:.2f} bits/token")

# Print most common tokens
print("Most Common Tokens:")
for token_id, count in token_counts.most_common(10):
    print(f"  ID {token_id}: {count} times")

Multimodal Processing (ModalEngine)

If ImpressionCore includes a ModalEngine (e.g., in src/core/modal_engine.py), it simplifies handling multiple data types.

# Conceptual Example
from src.core.modal_engine import ModalEngine, ModalityType

engine = ModalEngine()

# Register the trained tokenizers

Custom Tokenizers

You can integrate your own tokenizers by ensuring they adhere to the expected interface (typically encode and decode methods).

class MySimpleTokenizer:
    def __init__(self):
        # Simple space splitting
        self.vocab = {'<unk>': 0}
        self.rev_vocab = {0: '<unk>'}
        self.next_id = 1

    def encode(self, text):
        ids = []
        for word in text.lower().split():
            if word not in self.vocab:
                # Add to vocab dynamically (simple example)
                self.vocab[word] = self.next_id
                self.rev_vocab[self.next_id] = word
                self.next_id += 1
            ids.append(self.vocab[word])
        return ids

    def decode(self, token_ids):
        return " ".join(self.rev_vocab.get(id, '<unk>') for id in token_ids)

Tokenization Best Practices

  • Consistency: Apply the *exact same* preprocessing (resizing, normalization, text cleaning) during inference as was used during tokenizer training.
  • Vocabulary Fit: Train tokenizers on data representative of what they will be used on. A tokenizer trained on news articles might perform poorly on code.
  • Text Normalization: Decide on a consistent strategy (lowercase, punctuation removal, unicode normalization) before training and apply it always.
  • Image Resolution: Train and use the image tokenizer with the expected image size.
  • Codebook Size (Images): Larger codebooks capture more detail but increase memory and computation. 8192-16384 is a common range.
  • Evaluate: Check reconstruction quality (PSNR/SSIM for images) or downstream task performance to assess tokenizer effectiveness.
