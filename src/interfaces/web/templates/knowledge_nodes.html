Working with Knowledge Nodes

Understanding Knowledge Nodes

Knowledge Nodes are the fundamental building blocks of the Universal Knowledge Store (UKS). They represent concepts, entities, facts, or relationships and can be linked together to form a comprehensive knowledge graph.

Creating Knowledge Nodes

Nodes can be created individually and then linked together to form more complex knowledge structures:


from impressioncore.uks import UniversalKnowledgeStore

# Initialize the UKS
uks = UniversalKnowledgeStore()

# Create a basic node
book = uks.create_node(
    label="Book",
    attributes={
        "has_pages": True,
        "readable": True,
        "typical_use": "storing and sharing information"
    }
)

# Nodes can be created with unique IDs
textbook = uks.create_node(
    node_id="node:textbook",  # Explicitly set ID
    label="Textbook",
    attributes={
        "educational": True,
        "contains_exercises": True,
        "target_audience": "students"
    }
)

The create_node() function returns a dictionary-like object that you can manipulate:


# Accessing node properties
print(book["label"])        # "Book"
print(book["has_pages"])    # True

# Modifying node attributes
book["digital"] = False
book["typical_lifespan"] = "decades"

# Checking if attributes exist
if "readable" in book:
    print("Books are readable!")

Node Structure

Each Knowledge Node has the following core components:

Component Description Example
node_id Unique identifier for the node "node:book-1"
label Human-readable name for the concept "Book"
attributes Key-value pairs representing properties {"has_pages": True, "readable": True}
relationships Connections to other nodes [{"type": "is_a", "target_id": "node:physical-object"}]
metadata Information about the node itself {"created_at": "2023-05-01T15:30:00Z"}

Working with Node Relationships

Nodes become more powerful when linked together with relationships:


# Create a parent node
literature = uks.create_node(
    label="Literature",
    attributes={
        "creative_work": True,
        "cultural_artifact": True
    }
)

# Establish relationships
uks.add_relationship(
    parent=literature,
    child=book,
    relationship_type="includes"
)

# Relationships can have additional properties
uks.add_relationship(
    parent=book,
    child=textbook,
    relationship_type="is_parent_of",
    properties={
        "strength": 1.0,
        "exclusive": True
    }
)

Common Relationship Types

These are some common relationship types used in knowledge graphs:

  • "is_a": Indicates class membership or type
  • "has_part": Composition relationship
  • "related_to": General association
  • "instance_of": Concrete instance of a concept
  • "causes": Causal relationship
  • "precedes": Temporal ordering
  • "located_in": Spatial relationship
  • "used_for": Functional relationship

You can define your own relationship types based on your knowledge domain needs.

Querying Nodes

The UKS provides several methods to retrieve nodes and extract information:


# Get a node by ID
fiction_book = uks.get_node("node:fiction-book")

# Get node by label
science_book = uks.get_node_by_label("Science Textbook")

# Find nodes with specific attributes
educational_materials = uks.find_nodes_by_attribute("educational", True)

# Find nodes related to a specific node
book_subtypes = uks.get_children(book)

# Complex queries using filters
science_fiction_books = uks.query_nodes(
    lambda node: (
        node.has_parent_with_label("Fiction") and
        node.has_parent_with_label("Science") and
        node["readable"] == True
    )
)

Node Traversal

Navigate through the knowledge graph to discover relationships:


# Get all ancestors of a node (parents, grandparents, etc.)
all_ancestors = textbook.get_ancestors()

# Get direct parents
parents = textbook.get_parents()

# Find the shortest path between two nodes
path = uks.find_path(textbook, literature)

# Walk the graph in a specific pattern
uks.traverse(
    start_node=book,
    visitor_fn=lambda node: print(node["label"]),
    max_depth=3,
    traversal_type="breadth_first"
)

Advanced Node Operations

Node Merging

Combine information from multiple nodes:


# Merge information from two nodes
fantasy_fiction = uks.merge_nodes(
    uks.get_node_by_label("Fantasy"),
    uks.get_node_by_label("Fiction"),
    new_label="Fantasy Fiction",
    merge_strategy="union"  # Can be "union", "intersection", or custom function
)

Node Comparison

Compare the similarities and differences between nodes:


# Calculate similarity score
similarity = uks.calculate_similarity(textbook, reference_book)
print(f"Similarity: {similarity:.2f}")  # Value between 0.0 and 1.0

# Find common attributes
common_attrs = uks.common_attributes(textbook, reference_book)
print(f"Common attributes: {common_attrs}")

# Find differences
differences = uks.node_diff(textbook, reference_book)
print(f"Differences: {differences}")

Node Versions and History

Track changes to nodes over time:


# Get version history of a node
history = uks.get_node_history(book)

# Revert to a previous version
uks.revert_node(book, version="v2")

Best Practices for Knowledge Nodes

  • Consistent Naming: Use a consistent naming convention for node labels.
  • Attribute Types: Keep attribute values to primitive types (strings, numbers, booleans, lists) when possible.
  • Documentation: Add documentation attributes to complex nodes explaining their purpose.
  • Granularity: Break complex concepts into multiple linked nodes rather than creating overly complex individual nodes.
  • Relationships: Use specific relationship types rather than generic connections.
  • Validation: Implement validation rules to ensure data consistency.
